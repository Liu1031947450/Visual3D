# 技术验证报告

版本：1.0 · 2026-09-21 · OCULUS 眼球三维演示

## 1. 目标与实现

验证从“打开页面 → 渲染眼球 → 拖动旋转 / 缩放 / 平移 → 多平面剖切 → 查看结构图文”，以及从“选择本地文件 → 格式解析 → 替换模型 → 显示 / 动画 → 失败回退”的完整流程。

采用 Vite + 原生 JavaScript + Three.js，不引入 UI 框架或后端。Three.js 版本 0.186.0，精确依赖由 lockfile 固定。使用 OrbitControls、GLTFLoader、OBJLoader、MTLLoader 与 AnimationMixer。界面图标来自 Lucide，交付文档由 Marked 渲染；仅渲染项目自带 Markdown，不接受用户 HTML。

眼球以九个解剖分组预先导出为 `public/models/eye.glb`，包含虹膜纹理、巩膜纹理、内壁血管、睫状体褶皱、悬韧带、晶状体和视神经。页面启动及恢复默认模型时通过 GLTFLoader 读取 GLB，不再运行生成器。它仍是交互技术示意，不是经过医学审核或测量标定的解剖资产。

## 2. 与参考示例的对应

参考：Three.js 官方 `webgl_clipping_intersection`。

| 示例能力 | 本项目实现 |
| --- | --- |
| 多层球体局部剖切 | 九类眼球结构，材质共享三个世界空间剖切平面 |
| `clipIntersection` | “交集剖切”开关，对应负半空间交集与并集 |
| 平面位置参数 | X、Y、Z 三个滑块独立控制，每轴可启停 |
| PlaneHelper | “显示剖切平面”开关 |
| OrbitControls | 旋转、缩放、平移，附相机重置和视角预设 |

剖切只改变片元可见性，不重建几何。因此切面变化不意味着三角面统计同步降低；当前不执行实体截面封口或 CSG 布尔运算。

## 3. 格式兼容性与实现难度

| 项目 | GLB 2.0 | glTF 2.0 | OBJ + MTL |
| --- | --- | --- | --- |
| Three.js 加载器 | GLTFLoader | GLTFLoader | OBJLoader + MTLLoader |
| 资源组织 | 常见为一个二进制文件 | JSON、bin、图片，需路径映射 | 文本几何、材质库、图片 |
| PBR | 标准支持 | 标准支持 | MTL 不能完整表达现代 PBR |
| 透明 / 透射 | 基础透明与相应扩展 | 同 GLB | 基础透明；无 glTF 透射扩展 |
| 节点层级 | 保留 | 保留 | 不应当作可靠骨骼层级容器 |
| 动画 | 骨骼、节点、morph | 同 GLB | 无标准动画交付 |
| 当前 demo | 未压缩文件、内嵌资源、动画控制 | 外部资源多选、动画控制 | 一个主 OBJ、最多一个引用 MTL、贴图多选 |
| 接入难度 | 低：文件管理简单 | 中：附件缺失与路径处理 | 中：几何容易；材质转换与语义恢复工作更多 |

复杂效果最省事的正式交付是 GLB，不是因为扩展名更快，而是因为资源丢失风险小、结构和材质表达完整。OBJ 适合静态几何备用，不是等价无损备份。

Draco、Meshopt、KTX2 的加载依赖对应解码器。本 demo 未启用这些解码器，不能把 GLTFLoader 的支持清单当成项目已验证的能力。

## 4. 测试方法

### 自动检查

`npm test` 检查文件选择、体积限制、多主文件、重名配套文件，以及剖切交集/并集、关闭轴、平面偏移与完整模式。

`npm run test:browser` 使用 Playwright 驱动已安装的 Chrome。默认测试地址为 `http://127.0.0.1:5188`，可用 `BASE_URL` 修改。脚本自行生成一份包含两张网格、贴图和一段节点动画的标准测试资产，以同一份几何导出 GLB、分离式 glTF 和 OBJ，实际走页面导入入口。OBJ 无动画，材质不与 glTF 完全等价。

浏览器检查不只断言 DOM：对 WebGL canvas 下采样读取像素，验证非空、切面变化和自动旋转确实改变图像。同时保存桌面、手机、分层视图与截图下载结果。

### 性能取样边界

- 本地解析时长：文件到 File 对象后，包含 loader 解析、图片解码、模型分组及包围盒归一化；不包含网络下载、首次导入模块或首次 GPU 着色器编译。
- 每种格式复用同一页面测试五次，取中位数，属于**热环境本地解析**；不是冷启动或弱网数据。
- 帧间隔：同一 1440×1000 页面、DPR 1、完整模型模式，取 60 个 requestAnimationFrame 间隔的均值，受屏幕刷新率和运行环境影响，不是 GPU timer query。
- 三角面及 draw calls：读取 Three.js renderer.info，包含场景辅助网格，不是纯资产统计。
- 保存原始结果为 `test-results/verification.json`；它是每次运行生成的产物，可复测，不提交到 Git。

## 5. 实测记录

初轮实际浏览器观察：桌面 1440×1000、1910×958 均能渲染，程序化眼球的渲染统计约 88.6k 三角面、20 次绘制。帧率随窗口和采样时段变化，不将单次 FPS 读数当作跨设备承诺。

### 实际测试环境

2026-09-21，本地 macOS、Apple M2，Chrome 153.0.8010.53（Playwright 无头模式），WebGL renderer 为 `ANGLE (Apple, ANGLE Metal Renderer: Apple M2, Unspecified Version)`。桌面 1440×1000，DPR 1；移动布局另以 390×844 检查。原始记录中的初次加载采样为 43 FPS，包含启动阶段，不能当作模型稳定运行帧率。下表对应 2026-09-21 11:24（Asia/Shanghai）启动的回归记录。

### 同几何格式比较

| 格式 | 总文件体积 | 5 次本地解析中位数 | 60 帧平均间隔 | 渲染三角面 / draw calls | 动画 |
| --- | --- | --- | --- | --- | --- |
| GLB | 188,116 B | 4.60 ms | 16.67 ms | 7,970 / 4 | 1 段，播放通过 |
| glTF + bin + PNG | 188,059 B | 3.80 ms | 16.67 ms | 7,970 / 4 | 1 段，播放通过 |
| OBJ + MTL + PNG | 974,598 B | 35.20 ms | 16.67 ms | 7,970 / 4 | 格式不支持 |

GLB 与 glTF 的官方 Validator 校验均为 **0 Errors、0 Warnings**，报告包含图片与外部二进制资源校验。此结论针对脚本生成的测试资产，不是对任意建模文件的担保。

该小样本中 OBJ 文本文件更大、解析更慢，但三者加载后的帧间隔接近，符合相同几何的预期。不能把比例推广到其他模型，更不能由这些热环境数据推出弱网首屏时长。GLB 和 glTF 的微小体积差也不具有普遍排序意义。

2026-09-21 默认 GLB 改造：导出文件 3,749,180 字节，Khronos Validator 校验 0 Errors、0 Warnings；九个分组、16 个材质与两张内嵌贴图保留。同一浏览器、同一相机下，将画面采样为 160×160 RGBA，与原生成器比较的平均通道差约 0.000059 / 255；这仅验证当前场景外观，不代表任意替换模型的医学或视觉正确性。自动化另覆盖默认 GLB 请求、加载状态、恢复失败保留原模型、默认文件缺失或缺分组时的错误提示，以及部署前缀。

## 6. 资源与性能设计

- 像素比限制为不高于 2，减少高 DPI 设备的片元负载。
- 复用合并后的血管和褶皱几何，减少大量小对象带来的绘制次数。
- 导出工具使用固定随机种子生成纹理，运行时直接读取 GLB 中的内嵌图片。
- 透明表面尽量少；玻璃体和角膜用近似透明效果，避免对真实组织光学作出承诺。
- 本地文件总大小限制 50 MB，资源加载成功才替换原模型；失败时保持旧模型和页面可用。
- 替换模型时释放旧几何、材质和纹理；停止旧 AnimationMixer 动作。
- 不引入后端、数据库和账号。没有上传存储、服务器端病毒扫描或多人审核系统。
- 为截图启用了 preserveDrawingBuffer；正式大规模场景可改为按需渲染后导出，以评估这项设置的性能成本。
- 保持渲染循环用于交互、帧率与动画；页面隐藏时跳过渲染。无交互长时间展示的节能场景可进一步改为按需渲染。

## 7. 明确未验证与未实现项

1. 尚无建模人员提供的正式眼球模型，因此无法验证其真实拓扑、贴图、扩展、医学尺寸与视觉一致性。
2. 没有真实 iOS Safari / Android 中低端手机的 GPU 性能数据。手机截图来自桌面浏览器视口模拟，不是实体手机兼容证明。
3. 没有对 Draco、Meshopt、KTX2、极大网格、复杂骨骼、morph 动画或全部 glTF 扩展逐项验证；动画检查以节点位移动画为代表。
4. 没有实体切面封口、运行时 LOD、测量工具、光学仿真、病理模型或 DICOM 体数据读取。
5. 没有生产 CDN、弱网、离线缓存、首次下载时间、长期内存压力或多浏览器自动矩阵测试。
6. GLTFLoader / MTLLoader 可能保留不同材质语义；“加载成功”不等于与建模软件像素级一致。
7. 本地导入按唯一文件名匹配资源，多目录同名图片、多个主模型、多个 MTL 不在支持范围。
8. 自动归一化只是显示变换，滑块和视觉大小都不构成毫米测量。

## 8. 下一轮专业资产接入

先交一份小体积未压缩 GLB，通过 Khronos Validator 后，固定相机、光照、曝光和切面参数，与源软件截图比对。再对目标设备逐项测量：冷加载、首个有效三维帧、稳定帧耗时、绘制次数、纹理/几何数量和长时间交互内存。

只有在测量显示瓶颈后才加入网格压缩、GPU 纹理压缩或 LOD。优化前后使用同一模型版本与相同视觉验收条件，并保留未压缩基准用于排查。
