# 3D模型数据导出规范

版本：1.0 · 2026-09-21 · 适用项目：OCULUS 眼球解剖展示

## 1. 范围与交付结论

**正式交付优先使用未压缩的 glTF 2.0 二进制文件，即 `.glb`。** 一个文件内包含网格、材质、贴图与动画，便于传输和版本管理。保留 Blender、Maya 或 3ds Max 源文件，供修改，不直接交给浏览器展示。

当前 demo 使用程序化生成的眼球，不包含经过医学审核的专业眼球资产。模型的层厚、血管、透明度与瞳孔表现经过可视化简化；不得据此测量或诊断。此文档中的面数、文件大小和帧率是**项目起始预算，不是 glTF 官方限制或真实解剖参数**。

### 格式选型

| 格式 | 应交文件 | 可保留的数据 | 适用性与当前支持 |
| --- | --- | --- | --- |
| GLB 2.0 | `eye_right_v001.glb` | 层级、PBR 材质、纹理、骨骼、变形目标、动画 | 首选；当前支持未压缩文件，需自行确认扩展 |
| glTF 2.0 | `.gltf` + 所有 `.bin` + 所有图片 | 与 GLB 相同；资源分开存放 | 支持；导入时必须一起选择全部配套文件 |
| OBJ | `.obj` + 引用的 `.mtl` + 图片 | 静态几何、UV、法线、基础材质 | 静态备用；当前每个 OBJ 支持一个 MTL，不保留动画或现代 PBR 语义 |
| FBX / BLEND / MAX / MA | 建模源文件 | 制作工程与编辑信息 | 归档用；本 demo 不直接加载，需转为 GLB |

GLB 是 glTF 的二进制容器，**不是另一套材质标准**。同一模型转成 GLB 不意味着帧率自动高于 glTF；模型进入 GPU 后，性能主要受几何、材质、透明覆盖、绘制次数和像素数量影响。

## 2. 交付目录

```text
eye_right_v001/
  eye_right_v001.glb
  source/eye_right_v001.blend
  preview/front.png
  preview/side.png
  preview/section.png
  validation/eye_right_v001.report.json
  model-info.json
  CHANGELOG.md
  LICENSE.txt
```

分离式 glTF 的工作包可以含 `textures/` 目录，但当前页面采用多文件选择，不是 ZIP 或目录上传。**本地导入时请同时选中主文件、二进制数据和所有图片；图片文件名必须全包唯一。** 当前实现按文件名匹配资源路径，不支持不同目录下的同名图片。ZIP 仅用于传输，请先解压。

材质图片必须随交付包提供，禁止引用建模人员电脑上的绝对路径或远程网络地址。页面的模型导入只在本地浏览器解析，不上传文件；网络模型资源会被拒绝。初次页面加载的字体资源是独立的外部请求，与模型数据无关。

## 3. 尺寸、方向和变换

1. glTF 使用右手坐标系，Y 轴向上，线性长度单位为米。项目约定角膜朝局部 +Z、眼球上方朝 +Y。
2. 模型原点放在约定的眼球中心。眼球直径以毫米沟通，以米导出，例如直径 24 mm 的示意目标对应 0.024 m；最终以审核确认的模型尺寸为准。
3. 交付说明标记左眼或右眼，不能仅根据模型的 +X 方向判断临床左右。
4. 导出前确认缩放、旋转、镜像与法线；避免未处理的负缩放。带骨骼的模型不要在绑定后随意应用变换，必须先在源文件中验证动画。
5. 建模软件自身的向上轴可能不同，使用 glTF 导出器的轴转换，不要凭经验重复旋转。
6. 当前页面会用父级变换把导入模型居中并归一化到显示尺寸，保留内部节点的动画关系。页面剖切滑块使用**显示空间坐标**，不是毫米刻度，不能用于医学测量。

## 4. 部件与节点命名

至少拆分以下结构，每个结构独立命名、独立控制可见性，不要合成一个无法分选的整体。

| 节点命名 | 中文 | 交付关注点 |
| --- | --- | --- |
| `sclera` | 巩膜 | 有厚度的壳体，前部连接角膜 |
| `cornea` | 角膜 | 独立透明表面，避免重叠共面 |
| `iris` | 虹膜 | 环形结构，保留瞳孔开口和径向纹理 |
| `ciliary` | 睫状体 | 褶皱轮廓、与悬韧带的关系 |
| `choroid` | 脉络膜 | 与巩膜、视网膜的层次分离 |
| `lens` | 晶状体 | 独立双凸形体，正确法线 |
| `retina` | 视网膜 | 内表面和必要的血管细节 |
| `vitreous` | 玻璃体 | 独立透明体，不遮蔽内部结构 |
| `nerve` | 视神经 | 连接眼球后部，保留完整出口 |

推荐结构：`Eye_Root > sclera / cornea / iris / ...`。附属血管等可以放在相应结构子节点下，避免无意义的多层空节点。命名统一使用小写英文或带上述关键字的唯一名称，例如 `retina_vessels`。

当前导入器以**每个 Mesh**创建一条图层，通过网格名称包含上述关键词识别结构信息；不会自动合并同名节点为一组。缺少匹配的网格只显示原始名字及“导入网格”，不自动作解剖解释。程序化模型的分层展开仅对内置九组有效，导入模型的分层展开入口禁用，避免误移动骨骼或层级。

## 5. 几何、UV 与法线

- 导出前按最终三角面统计预算。四边面可能在导出时拆成两个三角形，UV 接缝和硬边会增加导出顶点数量。
- 独立薄组织应具备正确内外表面。建议需要剖切的壳体具有真实厚度和闭合边界，但避免同面重叠引发闪烁。
- 删除隐藏的制作残留、无用摄像机和灯光；保留需要展示的背面与眼球内部结构。
- 修复反向法线、退化面、自相交和未焊接裂缝。不要把 `DoubleSide` 当作所有几何问题的修复方式。
- 确保贴图需要的 UV 已展开；虹膜接缝不要穿过重点观察区域。法线贴图使用 glTF 所需的切线空间约定，导出或生成一致的切线；发现凹凸方向相反时先检查绿色通道及导出设置。
- 血管优先使用纹理/法线表现，只有对轮廓、剖切或近距离观察必要的血管保留几何。

## 6. 材质与纹理

优先采用 glTF metallic-roughness PBR 材质。复杂节点、程序噪声、毛发、离线渲染器材质不能假定会原样导出，必要时烘焙为图片。

| 数据 | 文件 / 通道约定 | 要求 |
| --- | --- | --- |
| 基础颜色 | Base Color，RGB 或 RGBA | sRGB；不把明显灯光与高光烘焙进颜色 |
| 粗糙度 / 金属度 | G = Roughness，B = Metallic | 非颜色数据；软组织通常按非金属制作 |
| 环境遮蔽 | R = Occlusion | 非颜色数据；可按导出器约定与其他贴图合并 |
| 法线 | Tangent-space Normal | 非颜色数据，使用与 glTF 一致的切线空间 |
| 自发光 | Emissive RGB | sRGB；常规眼组织不需要自发光 |
| 透明度 | Base Color A 与 alphaMode | 按需选择 OPAQUE、MASK 或 BLEND；不要把所有材质设成透明 |

建议首次交付 PNG / JPEG。带透明度的贴图使用 PNG；颜色图无透明需求时可用 JPEG。基础贴图以 2048×2048 为起点，局部次要组织可降为 1024×1024；尺寸属于预算，不是强制协议限制。避免默认全套 4K。

一张 2048×2048 的 RGBA8 纹理展开约 16 MiB，加完整 mipmap 约 21.3 MiB。图片文件只有 1 MB 不代表占用 1 MB 显存；JPEG/PNG 的下载压缩不会直接变成 GPU 纹理压缩。

### 透明、折射与特殊效果

| 目标 | 所需资产 | 前端配合与限制 |
| --- | --- | --- |
| 角膜湿润高光 | 独立角膜、法线、低粗糙度 | 环境反射 / clearcoat；不能用一张白色高光图片代替所有角度 |
| 晶状体折射 | 双凸几何、厚度、审核后的折射率 | 可采用 `KHR_materials_transmission`、`KHR_materials_ior`、`KHR_materials_volume`；需要逐设备验证 |
| 透明玻璃体 | 独立表面，最少重叠透明层 | 透明排序与透射成本可能成为瓶颈；内置 demo 用低透明度近似，不做真实光学计算 |
| 瞳孔变化 | 环形虹膜拓扑和 morph target 或绑定 | 需要导出的权重动画；不能简单缩放整个虹膜替代真实拓扑变化 |
| 组织表面细节 | UV、法线图，必要时颜色图 | 位移需要烘焙为几何或改用法线图；普通 glTF 不保证离线 displacement 一致 |
| 组织散射 | 美术参考图、预期效果说明 | 非基础 PBR 自动能力；需要另行评估，不承诺离线 SSS 原样呈现 |

当前 GLTFLoader 能识别多种 glTF 扩展，但本项目**未配置 Draco、Meshopt 或 KTX2 解码器**。第一轮交付不要启用这些压缩。如果后续启用，需分别接入 DRACOLoader、MeshoptDecoder、KTX2Loader，并部署匹配解码资源、配置路径与浏览器能力检测。不要仅改变文件后缀。

## 7. 剖切专项要求

实现对应 Three.js 的 `webgl_clipping_intersection`：开启 renderer 的 local clipping，在各材质上设置三个世界空间 Plane。平面带符号距离为负的一侧参与裁切。

- “交集剖切”开启：一个点位于所有启用平面的负侧才被裁掉，形成局部切口。
- 关闭：一个点位于任一启用平面的负侧就被裁掉。
- 每个轴可以单独启停，滑块修改该平面的 constant。
- 剖切作用于渲染阶段，不修改源文件、不重新导出网格、不减少原始三角面数量。
- **此 demo 不自动生成实体截面封口。** DoubleSide 只让背面可见，不会创造切口上的新面。壳体内外层可见，不等于拥有严格的体积剖面。

如要求“每个切口都显示均匀实体颜色”，应先确认是否只需要固定截面：固定截面可由建模端预切并补面；任意动态截面需前端另行实现 stencil 封口或几何布尔切割。前者对封闭网格、透明层、多平面交集及模型动画有额外要求，不能作为当前功能承诺。

## 8. 动画导出

GLB / glTF 可交付节点位置、旋转、缩放，骨骼和 morph weights 动画。将软件约束、驱动器和模拟烘焙为导出器支持的关键帧，检查旋转连续性与绑定矩阵。不要依赖源工程中的脚本或物理模拟。

每段动画单独命名，例如 `pupil_contract`、`lens_accommodation`。附说明：时长、是否循环、初始状态、适用结构。不要默认导出整条空时间线。当前导入后提供动画选择和播放/暂停，不自动播放；OBJ 没有相应动画支持。

## 9. 优化与 LOD

| 级别 | 总三角面起始目标 | 纹理参考 | 使用场景 |
| --- | --- | --- | --- |
| LOD0 | 60k–120k | 1K–2K，重点虹膜可另评估 | 桌面近距离剖切 |
| LOD1 | 20k–50k | 1K | 普通手机及中距离 |
| LOD2 | 5k–15k | 512–1K | 缩略视图或低性能设备 |

首屏资源建议不超过 8 MB，单套总资源先控制在 20 MB 以内，材质/网格尽量维持在约 40 项以内；最终依据目标设备实测调整。当前导入的文件总大小硬限制为 50 MB，它不是推荐生产预算，也不能保证 50 MB 以下的任意模型都能流畅运行。

LOD 必须保持同一原点、尺寸、方向、节点命名和必要的动画接口。分别导出 `eye_right_lod0.glb` 等，附对照预览。保留瞳孔和组织边缘，优先简化背面及微小血管。减少材质数量通常需要合并贴图，但不要因此合并需要独立剖切/隐藏的解剖结构。

基础 glTF 不会因为对象名含 `LOD1` 就自动切换；当前 demo **没有运行时 LOD 切换**。正式接入需使用 THREE.LOD 或自定义距离策略，并明确每级文件的加载时机。压缩也必须保留未压缩基准，比较清晰度、首帧时间、解码耗时和显存压力。

## 10. 导出与验收步骤

1. 在源软件确认尺寸、原点、命名、内部层次、UV、法线、材质和动画。
2. 导出选定对象为未压缩 GLB 2.0，材质与图片一起导出。具体面板选项以所用软件版本的官方说明为准。
3. 在一个全新场景重新导入导出的 GLB，检查颜色、方向、部件和动画是否还存在。
4. 使用 Khronos glTF Validator 生成报告。Errors 应为 0，Warnings 逐项说明；“校验通过”不代表医学正确或视觉效果已验收。
5. 放进本项目检查完整视图、交集/并集剖切、三个轴、隐藏图层、近距离细节、旋转和动画。
6. 记录目标手机和桌面的首帧、稳定帧耗时、文件体积、三角面、draw calls；不要只看建模软件中的帧率。
7. 将预览、验证报告、版本变化和授权文件一并交付。

最终人工勾选：无缺图、无远程依赖、尺寸正确、法线正确、名称稳定、各组织独立、切口无意外空洞、透明组织不遮蔽结构、动画正常、授权清楚、医学内容审核状态明确。
