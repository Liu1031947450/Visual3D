# 项目结构与新手入门

这份文档面向第一次阅读 OCULUS 代码的人。目标是弄清楚：**页面从哪里启动、眼球在哪里生成、操作如何改变画面、外部模型如何进入项目，以及修改后如何检查。**

当前代码已在模块入口、关键函数和流程分支补充中文注释。推荐一边读本文，一边搜索对应函数名，不必从第一行开始逐字读完所有几何参数。

## 1. 先用一句话理解项目

这是一个**纯前端三维展示程序**：浏览器中的 JavaScript 生成页面，Three.js 绘制可交互的眼球，原生 HTML 控件更新三维状态；侧栏文案来自本地数据，说明文档来自静态 Markdown 文件。

这里没有 React/Vue 组件树，没有后端 API、数据库或登录系统。默认眼球来自 `public/models/eye.glb`，由 `src/eye.js` 通过 GLTFLoader 加载。原几何与纹理生成器移至 `scripts/eye-source.js`，只在重新导出资产时运行。

页面上有两种 Canvas，先分清它们：

| 对象 | 谁创建/绘制 | 做什么 | 受什么影响 |
| --- | --- | --- | --- |
| `#scene` 内的三维 Canvas | `EyeViewer` / WebGLRenderer | 眼球、背景网格、示意阴影 | 相机、材质、图层、剖切、动画 |
| `#anatomy-diagram` 二维 Canvas | `main.js` 放入 DOM，`drawDiagram()` 绘制 | 固定眼球横断面示意 | 当前选择的结构 id |

二维图不会跟着三维相机转，也不是三维切面的自动截图。导入其他模型时它会隐藏，避免用固定图解释未知资产。

## 2. 开始前需要什么

| 准备项 | 用途 | 当前是否必需 |
| --- | --- | --- |
| Node.js 与 npm | 安装依赖、运行 Vite、执行测试 | 本地开发需要；按 README 的 Node 版本要求准备 |
| 支持 WebGL 2 的现代浏览器 | 真正运行和绘制三维页面 | 需要 |
| 硬件加速 | 支持更可靠的三维渲染和性能表现 | 建议开启；环境不支持时页面会报错 |
| HTML/DOM 与基础 JavaScript | 看懂元素、事件、函数、数组、对象、循环 | 入门知识 |
| `import/export`、Promise、`async/await` | 看懂文件依赖和异步导入 | 阅读导入流程前需要 |
| 建模软件或专业 GLB | 制作正式眼球数据 | 看默认 demo 不需要 |
| Chrome / Playwright 浏览器 | 运行浏览器自动化测试 | 跑 `test:browser` 时需要 |

### 第一次启动

在项目根目录打开终端：

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 5188 --strictPort
```

`npm ci` 按 `package-lock.json` 安装依赖；开发服务启动后，打开终端给出的地址，默认使用 `http://127.0.0.1:5188/`。**保持这个终端运行**，否则页面资源和热更新服务会停止。

如果 5188 已经被这个项目占用，直接访问已有服务即可。若被其他程序占用，换成未使用的端口，例如 5189，不要随意结束其他进程。`--strictPort` 会让占用问题明确报错。

不要双击 `index.html` 作为常规启动方式：这里依赖 Vite 处理 npm 包导入、CSS 和开发环境变量。

## 5. 从启动到第一帧，逐步追踪

| 步骤 | 入口 | 需要什么 | 做什么 / 得到什么 |
| --- | --- | --- | --- |
| 1 | `index.html` | Vite 服务、浏览器 | 建立 `#app`，加载 `src/main.js` |
| 2 | `main.js` 导入语句 | npm 依赖、其他源码模块 | 加载样式、图标、内容、Viewer 与加载器定义 |
| 3 | `app.innerHTML` | 已存在的 `#app` | 创建工具栏、`#scene`、侧栏、文件框、文档框 |
| 4 | `refreshIcons()` | 已插入的图标占位元素 | 将占位元素替换成 Lucide SVG |
| 5 | `initializeViewer()` → `await loadEye(eyeURL)` | public/models/eye.glb、anatomy 数据 | 显示加载状态，异步读取并校验九个分组，返回 model；失败保留错误和重新加载入口 |
| 6 | `new EyeViewer(container, model, onSelect, onStats)` | 已加载模型、有宽高的场景容器和两个回调 | 创建 Scene、Renderer、Camera、Controls、光照、切面 |
| 7 | `scene.add(model.root)` | 模型根对象 | 把眼球加入场景，记录展开前的基准位置 |
| 8 | `applyClipping()` / `resetCamera()` | 默认状态、模型材质、Plane | 设置剖切并把相机放到合适位置 |
| 9 | ResizeObserver | 场景元素实际尺寸 | 更新相机宽高比与 Canvas 绘图尺寸 |
| 10 | `renderLayers()` / `selectPart('retina')` | Viewer 的 model | 建立图层列表并显示初始视网膜信息 |
| 11 | `setAnimationLoop` 回调 | 浏览器帧调度 | 更新控制器、推进动画、渲染、投影标注、报告统计 |

构造函数只执行初始化一次；循环回调持续执行。点击按钮不是重新执行整个 `main.js`，而是运行此前注册的事件回调，修改现有对象。

模块顶层代码在加载时执行，但函数内部代码要等调用才执行。例如导入 `loadEye` 不等于已经加载眼球，真正读取文件发生在 `initializeViewer()` 调用它时。文档事件先绑定，模型加载过程中也能打开文档。

## 6. 最重要的数据结构：model

`loadEye()` 和 `loadModel()` 的实现不同，但都向 Viewer 交付下面这些字段。它是现有代码的约定，不是额外的框架或配置系统。

| 字段 | 内容 | 使用者与作用 |
| --- | --- | --- |
| `root` | Three.js 根 Group | Viewer 加入/移出场景，整体缩放和资源遍历 |
| `groups` | `Map<id, Object3D>` | 按 id 隐藏、高亮、记录位置；内置值是 Group，导入值是 Mesh |
| `materials` | 材质数组 | 统一更新切面、透明度、线框 |
| `entries` | 图文条目数组 | `renderLayers` / `selectPart` 生成名称、说明与顺序 |
| `builtin` | 是否符合内置眼球结构的默认 GLB | 决定能否使用固定标注、二维图与内置展开位移 |
| `animations` | AnimationClip 数组 | 导入模型的动画选项；内置模型为空数组 |
| `animationRoot` | 导入模型原始根对象 | Mixer 以这个根查找动画目标，不是居中缩放的新父组 |
| `filename` / `bytes` / `importMs` | 导入附加信息 | 显示名称、大小与本地准备耗时 |

### id 是连接图文与三维的关键

以视网膜为例：

```text
content.js: anatomy 中 id = "retina"
    -> eye.js: groups.get("retina")
    -> 视网膜 Mesh.userData.part = "retina"
    -> 点击图层 / 热点 / 射线命中
    -> main.js: selectPart("retina")
    -> viewer.select("retina") + 更新说明文字 + drawDiagram(...)
```

导入模型使用 `import-1`、`import-2` 等唯一 id。网格名包含 `retina` 等关键词时，加载器只借用相应科普文案，**不会把 id 改成 retina，也不能据此证明模型真的符合该解剖结构**。

`groups` 是查询表，不代表额外复制了一份三维对象。修改 `groups.get(id).visible` 就是在修改场景中的那个对象。

## 7. 用三个操作串起代码

### 操作 A：拖动 X 轴剖切滑块

```text
main.js 的 input[data-plane="0"] 触发 input
    -> 把 input.value 从字符串转成数字
    -> viewer.planes[0].constant = 新值
    -> 更新右侧 output 数字
    -> 下一帧 renderer.render(scene, camera)
    -> GPU 使用材质引用的 Plane，隐藏相应片元
```

为什么不需要重建模型？因为材质保存的是同一个 Plane 对象的引用。滑块修改了对象内部的 `constant`，渲染器下一帧能读取到新值。

为什么切换轴开关或交集模式要调用 `applyClipping()`？因为此时改变的是材质所用平面的列表或裁切逻辑，必须把新的配置应用到材质。

本项目平面方程是：`normal · point + constant = 0`。以 X 平面 `normal=(-1,0,0)` 为例，距离是 `-x + constant`；`constant=0.5` 时，`x>0.5` 位于负侧。滑块用的是**场景显示坐标，不是毫米**。

交集模式用全部启用平面负侧的交集裁切；非交集模式用这些负侧的并集裁切。所有轴关闭时不裁切，不允许因为空数组的 `every()` 为真就把所有点判成被切掉。

`isClipped()` 为什么还要再算一次？射线拾取检测完整几何，不会自动遵循 GPU 的显示裁切，所以点击筛选和标注需要 CPU 上的同规则判断。

**剖切没有切断源文件或减少原始面数，也不会自动生成实体封口。** `DoubleSide` 只让背面可见，不能替代切口的新面。

### 操作 B：点击“虹膜”图层

```text
renderLayers() 注册的 click 回调
    -> selectPart(entry.id)
    -> 在 viewer.model.entries 找当前条目
    -> viewer.select(id) 更新材质选中色
    -> #part-name 等 DOM 显示条目数据
    -> 图层/热点的选中状态同步
    -> 内置模型调用 drawDiagram(canvas, id)
```

选择不等于隐藏。右侧复选框走另一条事件，只设置对象 `visible`。隐藏对象也不等于删除它或释放资源，所以可以立即再次显示。

`viewer.select()` 会先保存原始 emissive，再叠加选中色。取消选择时还原原值，避免把用户导入的材质信息覆盖掉。

### 操作 C：导入一个 GLB

```text
点击 #import -> 原生文件选择器 -> change 事件
    -> 禁用导入按钮，显示读取状态
    -> await loadModel(FileList)
       -> validateFiles 校验主文件、体积、附件重名
       -> 为所选文件创建 Blob URL
       -> LoadingManager 将资源引用映射到本地附件
       -> GLTFLoader / OBJLoader + MTLLoader 解析
       -> 检查包围盒、包裹居中缩放父组
       -> 提取网格、材质、图文和动画，返回 model
       -> finally 撤销临时 Blob URL
    -> 成功后 viewer.replaceModel(model)
    -> 重建图层、选中结构、同步名称与动画控件
    -> finally 恢复按钮并清空文件框
```

`await` 让后续替换步骤等待加载完成。解析失败会进入 `catch` 提示错误，此前的模型没有被替换。选择器里的 `accept` 只是提示，不能替代程序校验。

GLB 通常只需一个文件；glTF/OBJ 需要同时选择对应 bin、MTL、贴图。当前按唯一文件名匹配，不会解压 ZIP；不能支持不同目录的同名图片。当前总大小上限为 100 MB，未配置 Draco/Meshopt/KTX2 解码器。

导入后的两层父组做“居中”和“最长边归一化”，保留原始节点层级，避免直接改动动画轨道使用的局部变换。它不等于做过医学尺度校准。

## 8. 三维代码里的常见名词

| 名词 | 在本项目中怎么理解 |
| --- | --- |
| `Scene` | 所有可渲染对象组成的场景 |
| `Camera` | 观察位置和投影方式；不是眼球模型本身 |
| `Renderer` | 把场景从相机角度画到 Canvas 的执行者 |
| `Geometry` | 顶点、面、法线、UV 等形状数据 |
| `Material` | 颜色、粗糙度、透明度、贴图和剖切规则等表面参数 |
| `Mesh` | 几何与材质组合成的可绘制对象 |
| `Group` | 多个对象的父级，便于一起移动和隐藏 |
| `Texture` | 给材质使用的图片；这里也可由 Canvas 生成 |
| `UV` | 顶点对应图片上的位置，通常在 0~1 范围 |
| `OrbitControls.target` | 相机围绕旋转、朝向的观察目标 |
| `Raycaster` | 从相机通过鼠标位置发射一条射线，找命中的网格 |
| `userData` | 挂在 Three.js 对象上的自定义数据，这里用 part 连接结构 id |
| `AnimationClip` | 动画轨道和关键帧数据；有数据不代表正在播放 |
| `AnimationMixer` | 将时间推进转换为对象动画变化的执行者 |
| `dispose()` | 主动释放 GPU 等资源，不能只靠移出 Scene 代替 |
| `this` | EyeViewer 方法中指向当前 Viewer 实例，例如 this.camera |
| 回调 | 把函数交给其他对象，在事件/帧到来时执行，例如 onSelect |

### 三种坐标不要混用

1. 局部坐标：Mesh 相对于父 Group 的位置，生成几何与动画常使用它。
2. 世界坐标：叠加父级变换后的场景位置，切面与射线命中点使用它。
3. 屏幕坐标：HTML 的 left/top 像素位置，热点需要先用相机 project，再从标准化坐标换成像素。

当前热点只为内置模型设置固定锚点，并加上展开位移；没有为任意旋转/缩放的导入层级自动生成热点，也没有检测其他网格对标签锚点的遮挡。

### 九个结构的标注如何显示

从 `eye.js` 的 `eyeAnnotations` 开始读：每条数据的 `id` 对应 `anatomy.id` 和 `model.groups` 的 key，`position` 是结构分组内的三维锚点，`side` 指定标签排在画布左侧还是右侧。它不是医学上的左右侧。

```text
eyeAnnotations + anatomy 名称 -> main.js 生成九个 HTML 按钮
    -> EyeViewer 缓存按钮与锚点
    -> updateAnnotations 加上展开位移并投影到屏幕
    -> 按左右列和投影高度排列，推开相邻标签、避开工具区
    -> 保留真实锚点位置，用连线连接标签
    -> 点击按钮仍走 selectPart(id)，同步模型选中和图文
```

默认剖切与默认视角下，九个结构都有标注，手机端也不省略。以下情况会主动隐藏对应标注：关闭“结构标注”、关闭结构图层、锚点被当前切面裁掉、锚点移出相机视野，或者正在展示外部导入模型。**数量完整不等于任何视角下都强制显示九个标签。** 内部锚点不会因为被其他结构遮住就自动隐藏，完整模式仍可通过标签选择内部结构。

新增或调整标注时，修改这一份锚点表即可，不要另写一份 HTML 列表。新增组织还需同步文案、模型分组与展开位移。先在默认剖切下检查锚点未被切掉，再检查旋转、展开和手机布局；`npm test` 会验证锚点与结构 id 一一对应，浏览器测试会检查实际可见数量、点击联动及标签重叠。

## 9. 渲染循环、动画与资源生命周期

每帧的顺序在 `viewer.js` 的 `setAnimationLoop` 中：

```text
计算距上一帧的秒数 delta
    -> 后台页面跳过实际绘制
    -> controls.update(delta) 更新阻尼与自动旋转
    -> 若 animationPlaying，mixer.update(delta)
    -> renderer.render(scene, camera)
    -> updateAnnotations() 更新 HTML 标注和轴方向
    -> 约每秒调用 onStats，更新 FPS/面数
```

“自动旋转”转的是相机，“播放动画”推进的是模型中的 AnimationClip，这是两个独立开关。`clipAction(...).play()` 只准备/激活动作；如果循环没有调用 mixer.update，动画时间不会推进。

切换模型时：停旧动作 → 清旧 Mixer 缓存 → 旧 root 移出 Scene → `disposeModel` 遍历释放几何、纹理和材质 → 装新 root → 记录新基准位置 → 准备新动画。

Blob URL 的 `revokeObjectURL` 释放浏览器文件引用，材质/纹理的 `dispose` 释放渲染资源，不是同一回事。场景环境纹理、相机等属于 Viewer 长期资源，不能在每次换模型时一起销毁。

当前没有整页 Viewer 的统一 `destroy()`。如果将来把它搬进会反复挂载/卸载的组件，需另外处理 ResizeObserver、动画循环、事件监听、Controls、Renderer 和环境资源；不要以为 `disposeModel()` 已处理了这些。

## 10. 我想改什么，应该去哪里

| 修改目标 | 优先位置 | 修改前需要知道 |
| --- | --- | --- |
| 改科普文字、中文名 | `content.js` 的 anatomy | 不要仅为了改显示名更改 id |
| 改眼球大小、层次、血管 | 替换默认 GLB，或修改 `scripts/eye-source.js` 后执行 `npm run export:eye` | 分组名、坐标、标注和材质必须一致；导出命令会覆盖资产 |
| 改虹膜纹理 | GLB 内嵌贴图，或生成器的 `irisTexture()` 后重新导出 | 图片是颜色图；保留 UV 与瞳孔中心一致 |
| 改整体明暗 | `viewer.js` 的光照/曝光 | 先固定相机比较；不要混同 UI CSS 与材质颜色 |
| 改初始视角或缩放范围 | `resetCamera()`、Controls 参数 | 注意手机容器宽度分支和 min/maxDistance |
| 改剖切默认值或行为 | planes/state、`applyClipping`、`isClipped`、main 的控件值 | GPU 与 CPU 规则、初始 UI 值必须一致 |
| 改展开距离 | `setMode()` 的 directions | 只适用于内置模型，恢复时依赖 basePositions |
| 增加或调整标注 | eye.js 的 eyeAnnotations、viewer.js 的 updateAnnotations | id 与组织对应；三维锚点和二维标签排版分开，不能只改 HTML |
| 增加新的组织 | anatomy、GLB 分组几何、eyeAnnotations、展开位移，必要时示意图 | 只加文案不会自动生成三维网格；九个 id 的测试也需按新范围调整 |
| 改模型导入能力 | `import-model.js` | 文件约束、路径映射、材质副本、动画根节点和失败清理 |
| 改侧栏或移动布局 | `style.css` | 查最终级联；场景尺寸影响相机和画布 |
| 改文档弹窗 | `main.js` 的 documents/openDocument 与 public/docs | 当前只信任本地项目文稿，Marked 不自动清洗不可信 HTML |
| 改性能报告或测试范围 | `scripts/browser-check.mjs` | 保留环境、样本和测量边界，不能只改报告数字 |

### CSS 阅读方法

`style.css` 已按规则和属性换行，并添加了区域注释。优先搜索页面上的类名，例如 `.workspace`、`.scene`、`.inspector`。再查 1550、1150、860、560 px 的响应式规则，最后查文件末尾的覆盖规则。

Canvas 看起来被拉伸，先检查容器尺寸与 `resize()`，不要先修改眼球顶点。样式没有按预期变化，打开浏览器开发者工具的 Computed/计算样式，确认是否被后面的同名规则覆盖。

## 11. 调试与最小练习

### 使用浏览器开发者工具

运行开发服务后打开控制台，`main.js` 在开发环境暴露了 `window.__atlas`。先使用只读检查：

```js
window.__atlas.state
window.__atlas.model.entries.map(entry => entry.id)
window.__atlas.model.groups.get('retina')?.visible
window.__atlas.planes.map(plane => plane.constant)
window.__atlas.camera.position.toArray()
window.__atlas.stats
```

`groups.get('retina')` 适用于内置模型；导入后应先查看 entries 中的 `import-*` id。生产构建没有这个调试入口，所以不能把控制台示例直接用于 preview 页面。

给 `main.js` 的 `data-plane` input 处理器打断点，拖动 X 滑块，观察 `input.value` 和 `viewer.planes[0].constant`。再给 `applyClipping()` 打断点，切换 X 轴启用框，对比两条链路的不同。

如果在控制台直接修改 Viewer，HTML 不一定同步，例如 `viewer.setMode()` 不负责按钮状态。页面完整流程应触发控件，或调用 main.js 的页面级协调函数；本项目没有自动响应式绑定。

### 建议按顺序做三个小练习

1. 只修改一条 anatomy.description，刷新检查文字变化且模型不变。
2. 只微调 resetCamera 的桌面初始位置，检查画面变化，再点相机重置确认一致。
3. 不改代码，跟踪一次滑块事件和一次本地 GLB 导入，记录每一层输入/输出。

每次练习只改一个目标，先记录原值。不要同时改相机、光照、贴图和几何，否则难以判断哪个改动导致问题。

## 12. 修改后怎么验证

### 第一层：快速逻辑检查

```bash
npm test
```

不需要服务或浏览器。检查文件边界、结构与标注 id 的完整对应、锚点坐标和剖切逻辑。它不会告诉你画面是不是好看，也不会实际解析图片。

### 第二层：生产构建

```bash
npm run build
```

确认源码可以打包。Three.js 所在 JS chunk 较大时已有体积提示，需要区分提示与构建失败。构建成功也不是浏览器交互通过的证明。

### 第三层：真实浏览器流程

保持开发服务运行，在另一个终端执行：

```bash
npm run test:browser
```

若开发服务换了端口：

```bash
BASE_URL=http://127.0.0.1:5189 npm run test:browser
```

没有系统 Chrome 时可安装 Playwright Chromium 后选择它：

```bash
npx playwright install chromium
BROWSER_CHANNEL=chromium npm run test:browser
```

`browser-check.mjs` 中普通代码在 Node 运行；`page.evaluate(() => ...)` 的函数在网页里运行，不能直接读取外层 Node 变量，要通过第二个参数传入。这是初读测试最容易混淆的边界。

测试会操作 UI、读画布像素、检查九个标注的显隐/点击/避让、生成三种格式测试模型、做标准校验并验证导入与错误回退。输出在 `test-results/`：

- `desktop.png`、`mobile.png`、`exploded.png`：界面复核。
- `model.png`：实际模型截图下载结果，不含 HTML 工具栏。
- `fixture.*`：本次生成的合成测试数据，不是正式眼球模型。
- `glb.validation.json`、`gltf.validation.json`：格式校验结果。
- `verification.json`：浏览器、渲染设备、格式性能与检查范围。

测试依赖开发模式的 `window.__atlas` 和 Vite 源码路径，**不要把 BASE_URL 指向生产 preview 当作同一套测试运行**。手机视口截图也不是实体手机性能证明。

### 第四层：生产部署检查

`npm run build -- --base=/Visual3D/` 后执行 `npm run test:deploy`，脚本会临时启动预览服务并检查真实构建产物，结束时自动关闭。它不读取 `window.__atlas`，可检查子目录中的 JS、CSS、标注、文档和首页跳转。设置 `BASE_URL` 可改测线上地址，具体命令见 README 的 GitHub Pages 部署部分。

### 纯注释修改的验证原则

如果任务仅增加注释、整理 CSS 格式和完善文档，不应更改业务行为。检查时比较修改前后的 JavaScript/CSS 语法树，忽略注释和位置信息，确认代码表达式、样式选择器与声明顺序不变，再运行已有测试和构建。标注补全等功能修复则需要新增对应的行为测试，不能用语法树不变作为通过标准。原有性能报告保留其测量时间，不把旧结果改称为新一次测量。

## 13. 常见问题怎么找

| 现象 | 先查哪里 |
| --- | --- |
| 打开地址却是别的项目 | 端口是否已被其他服务占用，以终端实际地址为准 |
| 页面空白或图标不出现 | 控制台是否报模块错误，npm 依赖是否完整，是否误用 file:// 打开 |
| 页面有 UI 但没有三维画面 | WebGL 初始化错误、硬件加速、#scene 实际宽高 |
| 滑块数值变了但画面不切 | 当前是否 section 模式、轴是否启用、材质是否调用 applyClipping |
| 切掉的地方还是能点中 | isClipped 与材质是否使用同一组世界空间规则 |
| 选中名称与结构不对应 | entries.id、groups 的 key、Mesh.userData.part 是否一致 |
| 标注缺少或重叠 | eyeAnnotations 是否覆盖全部 id，再查 labels 开关、图层 visible、isClipped、相机视野和 updateAnnotations 布局 |
| 导入说缺贴图 | 主文件与附件是否同时选择，附件名字是否唯一，是否仍引用远程地址 |
| 导入大文件卡住 | 100 MB 只是输入上限，不是性能保证；还要看面数、贴图、材质与设备 |
| 动画选项存在但不动 | animationPlaying 是否开启、mixer 是否在循环推进、轨道是否能找到目标 |
| 新模型仍显示旧图层 | 替换后是否调用 renderLayers 与 selectPart |
| 改了文档却没显示 | documents 中的 URL、Network 请求及是否仍在看旧构建产物 |
| 浏览器测试找不到 __atlas | 是否测试开发服务，页面是否初始化成功 |

## 14. 最后记住这条阅读路线

**先读 `index.html` 找入口，再读 `main.js` 找事件和回调，再进 `viewer.js` 看状态如何成为一帧画面。**

当问题是“模型从哪来”，读 `eye.js`；当问题是“文字为什么对应它”，读 `content.js` 与 `selectPart`；当问题是“外部文件怎么显示”，读 `import-model.js`；当问题是“布局为什么变形”，读 `style.css` 和 `resize()`。

掌握这一条完整链路，比一开始记住所有 Three.js 参数更重要：

```text
用户操作 -> main.js 事件 -> 修改 Viewer / model 状态
        -> 渲染循环画下一帧 -> 回调或投影更新页面
```

进一步接入专业资产时，再读《3D模型数据导出规范》和《建模需求与协作流程》；需要确认“实现了”和“测过了”有何区别时，读《技术验证报告》。内置模型、动态剖切、格式支持和医学审核是不同范围，不能相互代替。
